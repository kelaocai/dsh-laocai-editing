# 老财短视频成片

## 账号信息与逐片设计

- 主播：**老财**（"财"，财富的财，不是"蔡"）。频道名：**老财科技观察**。水印、关注按钮、字幕自报家门统一用这两个写法。
- 主战场：微信视频号，同步抖音。竖屏 9:16。
- 拍摄形态：**坐姿半身、固定机位**，办公室窗边，桌上有杯子。没有全身、站姿、走位镜头。手势在胸前，节奏靠推拉、字幕、素材切换来撑。
- **每条视频独立设计风格，没有账号统一视觉标准。** 根据本条主题、素材、情绪和用户要求确定配色、字体、字幕、构图、节奏与动画。不得自动沿用上一条、历史案例或模板的视觉风格；只有用户明确要求时才延续指定风格。
- 水印、进度条、开场包装、关注按钮和评论提示是否出现、放在哪里、如何呈现，都按本条视频决定，不作为必备组件。账号名称只约束文字写法，不约束视觉。
- 下文构图、字体及模板效果属于历史案例或技术实现参考，不是默认美术规范。使用模板前先按本条设计调整颜色、字体、布局、动效及开场结尾；不能因模板已有这些效果就直接套用。

## 视频内文字安全区（每次必读）

按用户已确认的 [安全区与遮罩规范](references/safe-area.md) 执行，无需再次索要规范：1080×1920 默认文字安全框 x=108–972、y=192–1728。标题、账号名、小字、花字和对白字幕均在框内；底部小字与字幕保持净距，字幕底板完整不透底。这是视频内长期排版约束，不限制逐片美术风格。**封面不套用此安全框，按目标比例满版输出，禁止缩图加黑边。**

## 视频封面

制作或修改封面必读 [多平台封面规范](references/covers.md)：先出三个方向供选（已选定则直接适配），按实际平台裁框满版输出，不加黑边，不默认写账号署名；最终逐张检查比例、四边、文字与人物。

封面默认导出表（用户确认，2026-11-01；宽×高）：

| 平台／用途 | 比例 | 导出尺寸 |
|---|---|---|
| 微信视频号封面 | **3:4** | **1080×1440** |
| 小红书视频封面 | **3:4** | **1080×1440** |
| 抖音主页封面 | **3:4** | **1080×1440** |
| 抖音竖版封面 | **9:16** | **1080×1920** |

以后默认按此表制作，无需用户再次提供比例；各版满版、无黑边、无默认账号署名。视频号3:4依据本次用户实际封面编辑器裁框，不沿用此前被否决的9:16加边方案，也不混用6:7旧规格。此表是用户工作默认值，不声称所有平台入口永久强制；若当前实际编辑器明确不同，则按实际裁框适配并说明。最终QC逐文件核对尺寸和比例。

## 流程

### 1. 口播转写：先定文字，再强制对齐到字

核心原则：**语音识别准确不等于时间戳准确**。识别负责"说了什么"，强制对齐负责"每个字在哪一刻"，分两步做。

**1a. 定文字（以实际说的为准）**

```bash
# 阿里云：文字最准，但长音频只给大段、没有逐字时间（在 meeting-asr 后端环境下运行）
cd <meeting-asr 后端目录> && .venv/bin/python <工作目录>/asr_raw.py <口播.mp3> host_asr.json
# 本地 whisper：给出自然分句，方便切字幕（不联网）
env -u HTTP_PROXY -u HTTPS_PROXY -u ALL_PROXY -u http_proxy -u https_proxy -u all_proxy HF_HUB_OFFLINE=1 \
  $BRIEF/scripts/.venv/bin/python <工作目录>/words.py <口播.mp3> words.json "专有名词提示"
```

用 whisper 的分句做骨架，用阿里云的文字逐句校正，写进 `edl.py` 的 `SUBS`（这里的时间只是粗略值）。whisper 错字多（"老财"写成"老蔡"、"咖啡馆"写成"开卫管"、"Robotaxi"写成"Robert Cab"），一律以阿里云和常识为准。主播口误的英文名（如把 PIX 读成 Pigs）字幕按正式品牌名写，并告知用户。

**文字必须和实际说的一致**：多说、漏说、改词都要先改进 `SUBS`，否则下一步对齐会漂。脚本原稿不能直接拿来对齐。

**1b. 强制对齐到字（Qwen3-ForcedAligner-0.6B，本地，115 秒口播约 15 秒）**

```bash
bash $T/setup_aligner.sh <工作目录>/qa          # 首次：建环境 + 下模型到 <本地模型目录>/（国内源）
python3 -c "from edl import SUBS; print(''.join(t.replace('，','').replace('？','').replace('、','') for _,_,t,_ in SUBS))" > script.txt
<工作目录>/qa/bin/python align.py <口播.mp3> script.txt aligned.json   # 每个汉字/英文词的起止时间
python3 subs_from_align.py aligned.json                                # → subs_aligned.json
```

`render.py` 检测到 `subs_aligned.json` 就自动改用逐字时间：**每个字在被说出的那一刻弹出**，英文词整体出现，关键词弹跳跟随该字自己的时间。没有这个文件时退回句级时间加固定错开。字幕默认比声音提前 50 毫秒出现，观感更跟手。

`aligned.json` 里字与字之间超过 0.45 秒的空隙就是停顿，可用来找口误、做自动初剪、或在停顿处切 B-roll。

实测（土豆巴士）：57 句里有 37 句的句级起点偏差超过 0.15 秒，最大偏 1 秒（"怎么样把人通过科技手段"）；对齐后字幕和口型、重音基本同步。

### 2. 选 B-roll：先看再定入点

- **先建镜头目录，查文字选镜头，不看图**（千问代看，见下文"看图分工"）：

  ```bash
  python3 $TOOLS/shotcat.py <素材目录> -o <工作目录>/shots_catalog.json   # 每段素材只描述一次，已建过的自动跳过
  python3 $TOOLS/shotcat.py --find <工作目录>/shots_catalog.json "话筒 唱歌"   # 关键词查；语义查询直接读 JSON
  ```

  目录里每个镜头有 `start/end`（场景检测给出的真实边界）和中文描述。**入点到出点不能跨过镜头边界**，否则会闪出下一镜的一两帧（土豆巴士第二版的跳帧大多是这个原因）；干净镜头不够长时用 `(入点, 速度)` 轻微慢放。
- 需要更细的判断时单问一帧：`python3 $TOOLS/vlook.py <素材> --t <秒> -q "画面里有人拿话筒唱歌吗？"`，返回一行 JSON（answer / confidence / detail）。不要凭印象给时间。
- 每个 B-roll 段**必须和当句台词语义对上**：说"KTV"就要有人拿话筒唱歌的镜头，说"办公室"就要有桌子电脑。没有对得上的素材时，先问用户要，不要拿相近画面凑（土豆巴士 v1 用车内休息区凑 KTV，被用户要求换成真 KTV 素材）。
- 网页截屏类素材（如美联社页面）用 `crop` 只取内嵌视频区域，做卡片；开头第一镜可以用整页，体现"外媒报道"。

### 3. 剪辑表 `edl.py`

一行一个镜头：`(开始秒, 类型, 素材键, 素材入点, 角标文字)`，切点卡在字幕分句时间上。以下构图是历史模板示例，按本条设计调整，不要求沿用：

| 类型 | 用途 | 构图 |
|---|---|---|
| `H` | 主播实拍 | 全屏；相邻主播段在正常和推近 1.14 倍之间交替，避免单机位发闷 |
| `B` | 横屏素材 | 居中 16:9 卡片 + 同源高斯模糊背景 + 青色四角取景框 + 缓慢推近 |
| `BP` | 外媒网页整页 | 页面横条居中 + 模糊背景 |
| `P` | 竖屏素材 | 全屏铺满 + 缓慢推近 |
| `G` | 全屏动画 | 底片用主播模糊画面，动画层完全覆盖 |

手机 HLG 素材（iPhone 10bit）在 `HLG` 集合里，会自动加对比度和饱和度校正，否则发灰。

### 4. 底片 `build_base.py`

按剪辑表逐段编码再拼接为 `base.mp4`。每段按帧数精确输出（`-frames:v`），日志会打印需要帧数和实得帧数，**有不符必须查**。拼接时用 `tpad=stop_mode=clone` 在尾部补帧，并加 0.35 秒淡出。

### 5. 字幕与动画 `render.py`

Pillow 逐帧画透明层，经管道交给 ffmpeg 叠到底片上，**只编码这一次**。以下是历史模板已实现的效果清单，仅供按需改造，不是每条视频的默认包装；颜色、位置、动效、线框及组件均按本条风格重新选择：

- **动态字幕**：逐字弹入 + 回弹（ease back），关键词黄色放大并二次弹跳，粗描边保证任何背景下可读。主播镜头字幕在 y=1500，素材镜头在 y=1560，避开主播面部和卡片。
- **角标**：左侧青色竖条 + 深色底，从屏幕外滑入，写"地点 · 事件"。
- **开头 BREAKING**：红色闪烁角标 + 大标题横向滑入。
- **全屏动画**：分体式结构（滑板底盘 + 上舱抬起 + 场景轮换）、数据卡（数字滚动 + 柱状生长 + 关键时刻弹出 ×3）、左右 VS 对比（台词说到哪条就弹出哪条）。都用发光线框风格（同一图层画两遍高斯模糊再叠原图）。
- **结尾**：评论区提示 + 关注按钮按台词时间依次弹出。

先用 `--preview <秒> <秒> ...` 出静帧拼图检查，确认后再整片渲染（115 秒片子约 1 到 3 分钟）。

### 6. 导出上传版

```bash
bash $T/export.sh final_noaudio.mp4 <主播原片.mp4> <输出.mp4> <总时长秒>
```

上传版参数（视频号和抖音通用、实测可用）：

| 项目 | 取值 | 原因 |
|---|---|---|
| 分辨率 | 1080x1920 | 两个平台竖屏标准 |
| 帧率 | 30fps | 素材大多 30fps，有的只有 25fps；硬升 60fps 只是重复帧，平台还可能降回 30 |
| 视频编码 | H.264 High 4.2，`-preset slow -crf 15 -maxrate 18M -bufsize 36M -g 60` | 实得约 10Mbps。平台会二次压缩，上传源越清晰越好；字幕动效和网格背景在低码率下最先出色块 |
| 色彩 | bt709，并在文件中写明 primaries/trc/colorspace | 防止平台误判色彩导致发灰 |
| 音频 | AAC 48kHz 256kbps，响度 -14 LUFS，尾部 0.4 秒淡出 | 96kHz 等非常规采样率会被平台重采样 |
| 封装 | `-movflags +faststart` | 边下边播 |

上传提醒：视频号选"原画"；抖音用 App 或创作者中心传原文件，不要先经微信转发（会被压缩）。

### 7. 与 Final Cut Pro 协作编辑与输出

用户要求在 FCP 编辑、合成、输出时，先读 [FCP 操作流程](references/fcp-workflow.md) 与 [FCPXML 编写参考](references/fcpxml.md)。让 FCP 实际承担时间线编辑、图层变换、素材变速、原生音量关键帧与最终合成，不把已烧录成片伪装成可编辑工程。

- 集中保存源素材、独立口播/BGM、透明包装、字幕、小窗及水印；按角色命名。PNG 的连接表达、原片静音和关键帧使用本机实测兼容写法。
- 以 FCP **最新原生回写**为下次修改基线；新版本另建事件/项目，保留人工编辑和旧版。共同文稿与稳定句编号驱动删句，所有图层共用同一整数帧映射。
- 时间用 Fraction，明确素材时间、父片段局部时间和项目时间；连接 offset 不可一律当全局秒数。语法校验、实际导入、原生回写、最终输出各自验证。
- 透明视频层可独立开关、调时、变换，但像素字幕不能直接改字。用户需原生改字时，另设计 FCP 标题或受支持的字幕导入；不要将 SRT 自动等同于任意可编辑标题。
- 使用已有 `templates/export_fcpxml.py` 前检查其结构与本机兼容性；旧模板不等于已验证的新工程。不沿用历史模板的模糊背景、装饰和字幕合层作为默认。
- 如果用户只要 FCPXML，按范围交付并准确说明是否做过应用内验证；如果要求 FCP 成片，则实际导出、核验、交付副本后才算完成。

## 质检清单（每版交付前过一遍）

交付包含封面时，另外执行 [封面最终 QC](references/covers.md)，视频 QC 不能代替封面检查。

**最终 QC 必须执行 [安全区与遮罩检查](references/safe-area.md)，核对实际导出中的文字越界、底部净距及背景透出；自动检测不能替代这一项。**

**先跑自动质检，再做视觉检查和连续播放。统计、几何检测和静帧不能替代动画连续性与最终听感的检查。**

```bash
python3 $T/qc.py <成片.mp4> <预期时长秒>
```

17 秒左右查完 12 项，不看图：分辨率、帧率、码率、采样率、时长、黑屏、冻帧、片尾和全片解码错误（马赛克）、响度、真峰值、长静音。有问题的行以 `[!]` 开头。

### 看图分工（省 token）

图片进入对话后会一直留在上下文里，**之后每一轮都重复计费**；千问看图后只回一行约 50 token 的文字。分三层：

| 层 | 交给谁 | 管什么 |
|---|---|---|
| 代码 | `qc.py`、ffprobe、ffmpeg 场景检测 | 帧数、时长、黑屏、马赛克、削顶、静音、**跳帧和闪帧、是不是同一个镜头** |
| 千问 | `$TOOLS/vlook.py`、`shotcat.py`（默认 `qwen3.8-flash`） | 画面里有什么、人在做什么、读画面文字和角标、素材和台词对不对、字幕挡不挡脸 |
| 当前主代理看图 | 当前工具提供的图像查看能力 | 审美判断（构图、动画好不好看）、版式效果图给用户选、千问拿不准的题 |

千问的用法：

- 是非题问法要具体（"画面里有人拿话筒唱歌吗"，不要问"这个镜头合适吗"），一题一事。
- `confidence` 低于 0.8，或答案直接决定剪辑取舍时，换 `--model qwen3.8-max` 复核；两个模型答案不一致才自己看图。
- 只关心某块区域时加 `--crop`（ffmpeg crop 表达式），比如美联社网页只看内嵌视频 `crop=2532:1420:528:252`。
- **不要让千问判断"两帧是不是同一个镜头"**：基准里三个千问模型都把主播原片的跳切判成同一镜头，又把手持摇镜判成换镜头。这个一律用场景检测。

实测（2026-10-18，土豆巴士 42 题基准，`<外部 vbench 工具（本包不含）>`）：

| 模型 | 素材内容 | 读文字 | 成片检查 | 同镜头 | 耗时 |
|---|---|---|---|---|---|
| qwen3.8-flash | 23/23 | 7/7 | 4/4 | 6/8 | 约 2 秒/题 |
| qwen3.8-27b | 23/23 | 6/7 | 4/4 | 6/8 | 约 2 秒/题 |
| qwen3.8-max | 23/23 | 7/7 | 4/4 | 6/8 | 约 3 秒/题 |

每题约 800 输入 token。有一题是千问对、Claude 错：Claude 看 160 像素缩略图漏看了话筒。**缩略图太小会漏细节，细节题交给千问看原尺寸（默认宽 768）**。换模型或千问出新版时先跑基准；新视频里确认过的判断随手加进题库。

当前主代理自己看图时：

1. **看之前先压小**：拼图总宽不超过 1200 像素，单格 160x284 到 216x384；只关心某个区域时只截那一块，比如字幕带就截 y=1400 到 1800。
4. **一次看完**：要检查的时间点攒在一张拼图里看，不要一张张看。
5. **版式修改先出效果图**：用真实画面合成 2 到 3 个方案放在一张对比图里，让用户选，不要改一版看一版。

JEV（TypeSafe）只接受文字形式的描述，不能直接看图，替代不了视觉检查。它适合的是纯文字判断，比如逐句比对口播和脚本有没有偏离、从多段文案里挑一段。

### 包装动画的检查要求

- 框内文字按实际字形边界居中，同时检查真实合成画面；不能只按字号或字体名义行高摆放。
- 箭杆与箭头用完整轮廓绘制，箭杆止于箭头肩部，不在尖端留下线帽凸起；使用矢量或足够的抗锯齿。
- 先安排节点、标签和连线路径，再设计入场与动作顺序。连线、流动点不能穿过标签或卡片；目标节点入场稳定后再连接。
- 检查每段动画的入场、进展、停留、退场及切镜边界。几何避让逐帧检查，审美和叙事合理性仍须在真实底片、连续画面和实际导出中复核，不能只看几张静帧。
- 用户未要求的制作说明不要默认写进成片。制作过程、素材来源和校验记录放在工程或交付说明中；遵从用户对画面备注的明确取舍，不能用备注掩盖不准确的素材或伪造实录。

### 人工检查

1. 内容核对先交给千问：每个 B-roll 段问"画面和这句台词对得上吗"、每个主播段问"字幕挡没挡脸"、角标问"写的是什么"，用 `vlook.ask` 在脚本里批量跑，只看结果文字。
   再检查真实画面拼图和关键动画连续片段，包括开头3秒、动画各阶段、所有切点前后及结尾。
2. 字幕里的人名、频道名、品牌名、数字逐个核对（读 `subs_aligned*.json`，不用看图）。
3. 交付时如实说明哪些看过、哪些没看过，提醒用户完整通看一遍。

## 坑（改脚本时不要回退）

- **结尾马赛克**：画面比音频短一帧时，片尾没有完整画面，播放器会显示花屏或马赛克。解决：底片尾部 `tpad` 补帧 + 淡出，导出时 `-t` 卡死总时长。
- **不要二次编码画面**：合成音频时 `-c:v copy`。v2 先编码画面、合音频时又编码一遍，画质损失；v3 改成单次编码。
- **ffmpeg 没有 drawtext**：别在 ffmpeg 里写字，一律走 Pillow。
- **手机素材抽帧报错**（`Non full-range YUV is non-standard`）：滤镜末尾加 `format=yuvj420p`。
- **手机竖拍素材带 -90 旋转元数据**：ffmpeg 会自动转正，但 ffprobe 看到的宽高是转之前的，按转正后的方向构图。
- **Python 带 `-I` 运行时找不到同目录模块**：自己写的工作脚本不加 `-I`；读不受信任素材的独立脚本才加。
- **zsh 下 `rm -f a_*.jpg` 无匹配会直接中止整条命令**：清理时用 `setopt null_glob` 或换写法，否则后续命令不执行、检查图是旧的。
- **模型名加载 whisper 会联网撞代理**：用本地模型目录路径加载，并设 `HF_HUB_OFFLINE=1`。
- **qwen-asr 直接 pip 安装会卡死或失败**：它依赖的 nagisa（日语分词）在 Python 3.12 上要源码编译。用 `setup_aligner.sh`：免依赖安装 qwen-asr、手动装核心依赖、给 nagisa 和 soynlp 放空壳。必须用 Python 3.12（3.10 下其他依赖也会构建失败）。
- **shell 变量里放 `env -u ...` 再调用会报 command not found**：zsh 不会把变量内容拆成命令，直接 `unset` 代理变量即可。
