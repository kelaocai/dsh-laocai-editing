# Final Cut Pro 协作、操作与交付

适用：用户要求在本机 FCP 真正编辑、混音、合成、导出，或导出可继续协作的工程。以下兼容性和UI经验实测于 **macOS / Final Cut Pro 12.4 / FCPXML 1.14**；版本改变时重新做小样验证，不视作所有版本的固有规则。XML细节见 [fcpxml.md](fcpxml.md)，视觉案例见 [visual-design.md](visual-design.md)。

## 工程组织与可编辑性

按用户指定位置组织；本片迁移到 Movies，创建独立 Agent 资料库，原工作路径用 symlink 保持可追溯。先复制、核对路径与文件，再调整引用，不先删旧目录。资料库与外部媒体是两部分，`.fcpbundle` 不自动包含所有素材。

建议按职责组织（可按项目规模简化）：

```text
<工程根>/
  Media/Originals/      实拍、完整录屏、B-roll、原音乐
  Media/Audio/          无BGM口播、工程采样率音乐
  Media/Overlays/       图解、字幕、小窗的独立透明视频
  Media/Graphics/       白底、品牌图、黑白水印PNG
  FCPXML/               agent输入XML与FCP原生回写
  Agent/                时间映射、混音参数、脚本、来源与质检
  Exports/              FCP原始输出与审核文件入口
```

独立源素材事件用于查找原片；正式版本各自建事件与项目。按角色分主画面、产品、录屏、背景、小窗、图解、字幕、水印、dialogue、music。lane 负责连接层位，role 负责筛选与开关，两者都不能简单等同于传统多轨编辑器的固定轨道。

优先让 FCP 承担素材入出点、变速、位置缩放、原生混音与最终合成。复杂程序动画可用透明 ProRes4444；包装、字幕、小窗分开，而不是全部烧进主片。像素字幕可开关/调时/变换，**内容不能直接改字**，改字需重渲；如需原生可改字，额外设计标题或字幕方案并实际验证。不把只有一条成片的时间线称为分轨可编辑工程。

## 与用户协作与版本基线

共同文稿为删句主版本，句编号保持稳定，例如本片001–073；维护累计删除集合与原始编号到时间映射。保留句显示当前时间码，删除句保留原始时间码，避免二次扣时。主播、字幕、录屏、小窗、音频与动画共用整数帧映射。

FCP 人工编辑后，先导出最新原生XML，agent从该回写修改，不用早期生成器覆盖人工调整。新版本另建事件和项目，移除/重建相应身份标识，保留旧版本；复制新项目时保留素材标识和未修改的剪辑信息。若只改水印，应比对非水印画面及音轨，不顺手改混音。

UI动作间若窗口或选区变化，刷新状态；出现同时操作迹象先协调由谁接管，已有授权则继续，不重复索要许可。使用当前环境支持的 UI 工具，不把 shell/AppleScript 当 UI 自动化捷径。

## 导入：四层验证

1. XML可解析、DTD通过、所有本地媒体路径存在。
2. 本机兼容性不确定或曾闪退时，先生成约2秒最小项目定位问题，再导完整工程；不要反复导同一失败版本。
3. 在 FCP 实际导入并打开目标项目，读警告内容，检查时间线、时长、首中尾画面和音轨。
4. 从 FCP 导出原生XML回读关键结构，最终核验真正导出的视频。每一层证明的事情不同，DTD通过不是应用导入成功。

本片曾在导入器 `FFXMLImporter addAssetClip` 崩溃；静态PNG连接由 asset-clip 改为 video 后成功。先修结构，保留失败文件/日志作诊断，不直接清理资料库或覆盖原工程。详见 XML 参考。

FCP导入目标实际受当前选中的资料库影响；不能只相信XML的 library location。可以暂时关闭旧库，再选中独立目标库导入；这只是关闭窗口中的资源库，不是删除。导入后核对事件确实位于目标库。

## 本机 UI 操作经验

- 先读当前 AX 状态，动作后再读；索引会重排，不跨状态复用。只在已观察到的控件上操作；AX不可用时看截图并定位，不盲点。
- 文件 → 导入 → XML；文件选择器选中实际文件，确认“导入”已可用，再点。导入进度消失后读警告，不用固定长等待推断完成。
- 导入新项目后**双击浏览器项目缩略图打开时间线**。只选中新事件不代表已打开新项目，之前时间线可能仍显示旧版。
- 导出XML或共享前先单击浏览器的项目图像；菜单禁用时先检查焦点与项目选择，不反复点击禁用项。核对项目名、范围与总时长，避免导出局部选区。
- 菜单无法通过 Escape 退出时，可用其 AX 暴露的 `Cancel` 次级动作；不要猜未暴露动作。保存框优先对文件名 `setValue` 后读回；切换目录可用 `super+shift+g`，对路径字段填完整路径并确认。
- 时间码定位可在时间线聚焦后 `ctrl+p`，输入八位时间码再 Return；本片为30fps，定位后检查 LCD，不能只相信输入成功。
- 每次导出后回到新版本时间线，收起阻挡画面的后台任务窗，方便用户接着审片。

## 原生混音与可闻性

独立无BGM口播与用户指定音乐各自为原生音频片段。原片/B-roll若仍带同一人声，确认它们实际静音，避免叠加回声；本机不能只依赖 srcEnable。

配乐以内容与节奏安排同节拍循环、重叠交叉淡化、结尾自然淡出。音量关键帧保留在FCP，参考本片是两段音乐、片尾4秒淡出；不是每条固定时长。先对齐独立音频与口型，再剪气口；不把BGM和口播先烧成单轨后伪称分轨。

测最终立体声成片，不只测单声道人声：本片mono口播约-14.2 LUFS，中置后约低3dB，于FCP补+3dB后最终约-14.29 LUFS、-3.17dBTP。这是本片实测，不是通用增益公式；按实际听感、底噪和真峰值决定。BGM是否真的进导出可用分轨/立体声侧信号辅助验证，时间线上存在不等于可闻。

用户曾要求加音效，后反馈听不到，最终明确取消并回退V6。最终方案是**无新增音效，保留BGM**。以后只在本条获得授权时加音效，按重点剧情和元素落点决定，不机械为每个切点加声。短音效以短时活跃窗口与实际手机听感检查；峰值、响度报告不能代替主观试听，不声称未做过的试听。

## FCP 实际导出与回写

浏览器选项目 → 文件/共享 → 导出文件。录音豆用视频和音频、H.264、1080×1920、30fps、Rec.709、AAC48k、仅保存；核对导出对话框实际值，不把其他编码器的CRF参数说成FCP参数。保存为新版本，保留FCP原始MOV。

文件出现不等于写完。查看后台任务的“共享”和“渲染”是否闲置、是否有报错，再用 ffprobe 读成片。FCP原生导出的MOV如需MP4，可无损转封装：

```bash
ffmpeg -v error -i 'FCP原生导出.mov' -map 0:v:0 -map 0:a:0 \
  -c copy -movflags +faststart '审核版.mp4'
```

如本机无法原生导出，准确说明阻塞；不要用另一个渲染器输出后宣称由FCP完成。

导出XML同样选中浏览器项目 → 文件/导出XML。FCP12.4当前1.14输出 `.fcpxmld` 包，内部 `Info.fcpxml` 是下一轮基线；保存后检查包内文件、项目名、帧数、媒体引用、增益和关键帧。不要把 `.fcpxmld` 当作普通XML文本直接解析。

## 验证与共享交付

- 核对实际帧数、时长、分辨率、恒定帧率、Rec.709、采样率与音画同步，首尾完整。
- 视觉局部修订：对全部修改段及切点前后帧检查，连续播放关键动画；比对修改区以外画面，允许正常重编码的小差异，不要求画面字节一致。
- 未改混音时比对压缩音频码流；相同hash可证明该轨字节相同。若编码不同但内容应相同，进一步比较解码PCM、响度和同步，不能仅凭hash不同就认定混音出错。
- 仅转封装时可对音视频各自做码流hash证明无重编码：`ffmpeg -v error -i 文件 -map 0:a:0 -c copy -f hash -`；视频用 `0:v:0`。
- 用户指定SMB目录时，先确认挂载，再复制为隐藏临时文件，完成后读取目标做 SHA256，与源一致后改正式名。保留旧版本；复制尝试或文件存在不算交付完成。
- 工程说明记录当前项目、最新回写、交付文件、可编辑范围和实际检查范围；工程参考路径与成片交付都指向真实存在文件。用户审核前不把自己的抽检称为全片人工通看。


### 配乐的时间覆盖不等于听感连续

录音豆V14在2:50被用户发现配乐消失：两条音乐片段实际重叠覆盖，问题是第二段取原曲120.27秒起，而原曲122–128秒本身接近静音，对应成片170秒以后。旧首段此时已结束。检查时间线无gap、全片总响度和音乐相关性仍可能漏掉局部近静音。后续先扫描原曲和候选循环的短窗能量，避开长breakdown，再对最终混音做全程局部音乐检查及接点听审。mono口播＋stereo音乐时可用L-R侧信号辅助确认音乐是否存在，但其电平不等于音乐整体响度，也不能替代试听；保留片头片尾有意淡化。
