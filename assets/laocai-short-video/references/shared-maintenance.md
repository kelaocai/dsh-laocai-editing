# Codex 与 Claude Code 共用技能的维护约定

维护本技能、更新经验或部署到另一台电脑时读取。内容为工具无关的剪辑流程；两端差异只限入口和可用工具，不维护两套正文。

## 唯一来源与本机入口

真正内容位于共享Git仓库的 `skills/video-audio/laocai-short-video/`。本机位置为 `<本技能资源目录>`；其他机器按实际克隆位置解析，不照搬此用户名路径。

`<本技能资源目录>` 和 `<本技能资源目录>` 是指向同一真实目录的符号链接，包含全部references和templates。任何一端修改都直接改变同一文件，无须双向复制、文件监听或定时同步。路径依赖由真实技能目录与实际已安装的辅助工具解析。

如果某工具或系统版本不识别当前入口，先检查其当前文档和技能列表；不要为了修复发现问题重新维护一份副本。Codex当前官方通用用户入口为 `<宿主机技能发现目录>`；本机保留已在使用的 `.codex/skills` 兼容入口。迁移入口时避免让同一名称出现两个可发现副本。不能仅凭磁盘链接检查就宣称已在另一应用的新会话实际调用成功。

## 一次更新流程

1. 解析入口到真实源目录，确认仓库状态；从当前最新文件修改，保护另一端未提交的工作。
2. 更新本技能主文档或专题参考，案例与通用原则分开；需要时在experience-log记实测结果。不要上传视频、字体包、API密钥或完整项目目录。
3. 在仓库根运行 `python3 scripts/manage.py check`；检查相对参考链接、脚本语法，必要时做实际业务验证。本机两端读取的源文件此时已经相同，不需要等待GitHub。
4. 审查 `git diff`，按实际变更提交本地Git。已配置远程且用户授权同步到该仓库时再 `git push`；没有远程就准确说明本地完成、云端尚未建立，不宣称已上传。
5. 已加载旧技能正文的会话可能保留旧上下文；重新读取技能，必要时新建会话或重新打开工具，不能保证当前对话的历史指令被热替换。

## GitHub与跨机器

建议使用用户指定的私有GitHub仓库，仓库只存技能文档、模板与维护脚本。GitHub负责版本历史、备份和跨机器传递；本机实时共用由符号链接实现。

另一台机器先克隆仓库，再运行 `python3 scripts/manage.py link`；目标若已有独立目录脚本会拒绝覆盖，须比较、备份后再切换。更新运行 `python3 scripts/manage.py pull`，仅允许工作区干净且快进拉取。冲突/分叉时停止，审查合并，不自动stash、reset、强推或覆盖未提交修改。

暂不安装定时任务或启动hook。需要后台定期同步时，先明确周期、机器、失败通知和本地修改策略，再按用户授权配置。Git提交推送不等于另一台机器已经拉取。
