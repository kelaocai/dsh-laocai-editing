# 视觉设计、排版与动画

适用：短视频视觉探索、改字体/配色、字幕卡、流程动画、水印和真实录屏包装。先区分通用检查方法与本条已选方案。这里的像素参数均是录音豆 1080×1920 案例，不能直接套在其他片子或其他分辨率上。

## 1. 逐片设计与审美决策

每条视频重新从主题、实拍、情绪和平台观看场景确定视觉方向。没有全账号统一色卡、字体或固定组件。参考视频借鉴叙事推进、信息密度和演示方式，不搬用产品结论，也不机械复制装饰。

有争议的视觉修改先用真实底片做少量有差异的对比：暗实拍、白底图解、软件录屏至少各一个适用场景；同时给完整画面实际比例和局部放大。用户选定后执行，不因已有授权反复要求确认。用户明确指定字体/颜色时直接落实并复核布局。

一个画面围绕一个主要信息组织层级：主结论、必要解释、辅助身份。让字号、字重、间距和色块承担层级，不靠不断增加边框、箭头、描边和装饰制造“科技感”。水印从属于内容；标题、关键词与字幕避免重复争夺注意力。画面边距和组件间距使用少量一致的尺度，并根据人脸、手势、产品位置调整。

制作说明放在工程与交付记录；用户未要求时，不把“示意、非软件实录”等备注堆在左下角。与此同时，不能伪造软件结果或用真实产品画面冒充另一个工具；图解的表现方式应与软件实录可辨。

## 2. 录音豆最终色卡（本片专用）

| 色彩 | HEX | 在本片中的作用 | 对应文字 |
|---|---|---|---|
| 黑 | `#000000` | 主文字、细分隔线、深色卡片 | 卡片内用白字，绿用于重点 |
| 紫 | `#7E3BED` | 重点标题、操作关系、部分强调色块 | 紫底主要用白字 |
| 白 | `#FFFFFF` | 图解背景、负空间、暗底文字 | 白底用黑字，紫作少量强调 |
| 荧光绿 | `#C6FF34` | 当前步骤、结论、关键词、高亮胶囊 | 绿底用黑字 |

最终包装不再出现橙色；原始实拍肤色、软件UI、品牌图片内部的自然颜色不属于包装换色范围，不做机械替换。RGB HEX 是设计值；视频转 YUV 与 H.264 后允许正常小幅色差，检查编码后的实色区域和整体观感。

白底承担解释性信息；实拍保留人物与场景质感。黑白形成稳定信息骨架，紫和绿用于有意义的重点，避免整页铺满高饱和色。黑白紫绿是本片的明确选择，后续新片没有要求时不能自动延用。

## 3. 字体、字幕与框内居中

录音豆最终：**MiSans Bold** 用于标题、关键词、字幕，**MiSans Regular** 用于说明；**钉钉进步体原版**仅用于右上角频道水印。阿里普惠体、得意黑是先前试验，不是本片最终选择。换字体后重新量中英文、数字、标点、斜体外伸、字宽和行高；不只替换字体文件路径。

字幕优先稳定、易读，与口播同步；强调少量关键词。框内文字按实际字形 bbox 水平和垂直居中，而不是按字体名义字号摆放。单行 Pillow 示例：

```python
left, top, right, bottom = draw.textbbox((0, 0), text, font=font)
x = (box_left + box_right - (right - left)) / 2 - left
y = (box_top + box_bottom - (bottom - top)) / 2 - top
draw.text((x, y), text, font=font, fill=fill)
```

多字重/多颜色拼接先测各段 advance，再检查整行实际可见边界；多行按完整块测量，确认上下内边距与视觉重心。描边、阴影存在时也要计入可见边界，不能再把整个框向下偏移补偿。最终要看编码后的字幕，而不只看 PNG。

本片字幕字高按内容在约58–64px适配；字幕透明带1080×210，放置 y=1615，框的局部范围约 x32–1048/y22–154，圆角24px。字形在框内居中；超宽先合理分行或缩字号，不压扁字形。这些坐标来自本片，其他镜头需要避开人脸、产品与平台UI重新确定。

## 4. 水印：最终确认的字标感

“老财科技观察”一行，不增加底框、额外短杠或图标。本片用户最终选择现成科技字体，不继续重绘 Logo。

- 字体：官方原版 `DingTalk JinBuTi.ttf`，36px；自然前倾来自原字形，不额外斜切、描摹或重制笔画。
- 右边距48px，上方可见字形边界28px；透明画布1080×1920，便于全画幅 PNG 用原点对齐，避免额外定位误差。
- 暗实拍：白字约96%不透明，轻黑阴影（约1px下移、1.2px模糊），无粗描边。
- 白底图解/本片录屏：近黑字 `#101114`，约94%不透明，无阴影无描边。
- 3倍尺寸渲染后 LANCZOS 缩小以抗锯齿；实际视频中核对斜体右缘、安全边距和清晰度。
- 黑白版本在镜头边界切换，相邻同色合并为连续段。V12为23段；不逐帧根据亮度变色，避免闪烁。其他视频若背景变化不同，重新取样判断，不能把全部 B-roll 都认作浅背景。
- 覆盖首尾，检查所有切点前后1帧、各段中间帧，防漏帧、叠旧水印、颜色选错和突然跳位。

官方来源：`https://page.dingtalk.com/wow/dingtalk/default/dingtalk/y-W5aF3_ZJwzulU0nceIl`。本次官方包随附《钉钉进步体法律声明》第3条允许商业/非商业使用，第4条限制转载、修改和转授权字体文件。保留来源与声明，只分享渲染图/成片，不把字体包打进交付。以后字体选择仍核实对应官方版本的授权；“免费下载”不等于任意商用或重制许可。不能因为字体是科技公司的就认定公开商用。

## 5. 动画：几何正确之外还要连续、优雅

箭头先确定完整轮廓：箭杆止于头部肩线，两侧斜边收敛为明确尖点；不让长线穿过三角形延伸成尖端外的小方块。用矢量或超采样抗锯齿，保持箭杆、头部宽度与图中尺度协调。

先排卡片和标签，再计算连线。路径避开文字与节点安全区，优先清楚的直线或少量折线；复杂流向拆为上下分段，不用循环圆点和交错线制造无意义活动。目标节点出现并稳定后连接，连接完成后再出现结果，顺序表达真实因果。

入场短而明确、缓动平滑，信息停留给足阅读时间；不让文字和卡片反复弹跳。动画服务于“发生了什么”，而不是每个元素都必须动。对每段检查入场、连接增长、关键落点、停留、退场及切镜，特别检查2:30类密集流程处的箭头重叠。

验证要分工：几何代码可逐帧检测越界/遮挡，但不能证明优雅；拼图能看构图，不能证明连续性。必须看真实底片上的连续片段及最终编码结果。改字、改字体或改布局后重新检查相关路径，不能复用旧碰撞结论。

## 6. 实录沉浸感与同步小窗

本片用醒目的 WorkBuddy 机器人和名称先建立工具身份，图解表达“WorkBuddy → WaveNote MCP → 云端录音”，实录聚焦“连接器 → 提问 → 调用 → 记录列表 → 摘要”。裁掉空白和长等待，放大实际操作区，不编造软件界面、录音数量或查询结果。

实录查询“最近3条”与口播“过去一个月”不同，应保留真实提问，屏幕说明实际查询范围。本片没有将真实结果伪改成另一个查询。

本片录屏卡片约 x60/y460、960×850；同步人脸小窗252×252、x752/y1330，边框与遮罩抗锯齿。每次从全屏主播切到图解时，按同一原片映射重新取人脸位置，避免从旧坐标裁到胸口；检查覆盖段首尾以及切回全屏时的单帧空窗。小窗不能拿前后静帧长期替代同步口型。


### 录音豆 V14 的浅色背景选择（2026-10-22）

用户从纸感、细网格、微点阵、柔和流线四款真实画面预览中选择04柔和流线。使用浅灰冷白约 `#F4F4F7`，低对比紫灰平行弧线集中在右侧及左下，文字主区留白；静态纹理避免随机噪声引起闪烁。只替换FCP独立背景PNG，不把纹理覆盖到软件UI、人物、字幕和包装上。先给图解及真实录屏的同画面对比与纹理局部放大，确认后再换全片。此为录音豆本片选择，不升级为账号统一背景。


## 发布界面安全区：挂购物车后重查

带商品卡的微信视频号界面会额外占用底部；状态栏、预约直播/返回/搜索按钮也可能覆盖顶部。不能仅用裸视频的9:16画布判断字幕、水印、标题是否安全。按本条实际发布场景取完整手机截图，核对视频在屏幕内的缩放和横向裁切，把UI占用区映射回项目坐标并加缓冲。移动字幕时同步避让主播小窗、说明标签和图解；背景仍全屏。检查所有场景、最长字幕、首尾和实际导出，并以重新上传后的手机预览作为平台实测，桌面示意图不能替代。

录音豆V16案例：iPhone17Pro完整截图1206×2622，通过916个特征内点估得视频到截图缩放约1.218725、水平偏移-55px，不能把截图按宽等比直接缩回。1080×1920工程关键内容约控制在x100–980/y260–1510；水印可见y265–303，字幕可见约y1396–1505。包装与插入素材用FCP原生统一仿射缩放0.72并向画布顶部245px处布局；字幕独立0.82缩放，小窗、产品与真实录屏同步变换以保持相对关系。此为该截图对应的本片实现，不是所有视频号、手机、UI状态的通用安全区或最优字号。
