# 视频素材梳理：从素材到脚本分镜

目标：用尽量少的 Token 读懂全部素材，画面和声音都要过一遍，最后产出三份东西：
1. `<项目名>_视频大纲与分镜脚本.md`
2. `<项目名>_分镜绘制需求.md`（给分镜师）
3. 素材研判表（写在大纲文档末尾）

所有中间产物放在素材目录下的 `_preview/`、`_audio/`、`_transcripts/` 里，原素材一律不改名、不移动、不删除。

脚本目录：`<本技能资源目录>/scripts/`（下文简写为 `$S`）

---

## 第 1 步：盘点与读文案

```bash
cd "<素材目录>" && ls -laR | head -150
textutil -convert txt -stdout <文案>.docx    # macOS 读 docx，不需要 pandoc
```

先把文案读完，记下其中的核心卖点、数据和需要背书的人物，后面看素材时专门对照着找。

## 第 2 步：画面预览（省 Token 的关键）

不要直接读视频或原图。每个视频只生成一张 3x2 的缩略拼图（6 帧，宽 600 像素）：

```bash
bash $S/preview.sh "<素材目录>"          # 输出到 <素材目录>/_preview/，并打印编号、路径和时长
```

**先建镜头目录，让千问代看**（Claude 只读文字）：

```bash
python3 <外部视觉工具 shotcat.py（本包不含）> "<素材目录>" -o "<素材目录>/_preview/shots_catalog.json"
```

场景检测把每段视频切成镜头，每个镜头取中间一帧交给千问（默认 `qwen3.8-flash`）写一句中文描述和关键词，连同镜头起止时间存进 JSON。读这个 JSON 就能知道每段素材拍了什么、每个镜头在哪一秒，写分镜时直接引用。照片同样可以问：`python3 <外部视觉工具 vlook.py（本包不含）> <照片> -q "..."`。看图分工、准确率和注意事项见 laocai-short-video 的"看图分工"一节；要点是千问看内容和文字很准，但判断不了"两帧是不是同一个镜头"。

拼图还要不要读：
- 目录描述足够写脚本时，不读拼图。
- 需要判断画面好不好看、能不能当开场镜头这类审美问题时，每组素材（每个子文件夹）挑 1 到 2 张代表性拼图来读，内容相同的同组素材不必每张都看。
- 照片用 `sips -Z 400` 缩小后再读，每组只抽 1 到 2 张。
- 在回复里如实说明哪些是自己看过的、哪些是千问描述的、哪些是按同组推断的，不要假装全看了。

## 第 3 步：拆音频（画面看不出的信息都在声音里）

画面只能告诉你"有什么"，台词才能告诉你"谁说了什么"。这一步不能省，它能纠正画面上的误判，比如把受访者当成主持人。

### 3.1 提取音轨

```bash
bash $S/extract_audio.sh "<素材目录>" [最小体积MB，默认 5]
# 输出 _audio/NN_文件名.mp3（16kHz 单声道 48kbps，约 0.35MB/分钟）
```

### 3.2 本地预判有无人声（不联网，免费）

```bash
bash $S/voice_check.sh "<素材目录>/_audio"
```

首次运行会自动建虚拟环境，用阿里云 pip 镜像安装 faster-whisper，约 260MB。模型直接读本地 HuggingFace 缓存里的 `faster-whisper-small`，不联网。缓存不存在时，按全局规则用 hf-mirror 下载，不要走代理。

判定分四档：

| 标签 | 含义 | 处理 |
|---|---|---|
| 有人声 | 清晰对白或采访 | 送阿里云 |
| 存疑 | 语音检测为 0，但硬转能转出内容，多为人声被背景音乐盖住 | 送阿里云 |
| 少量人声 | 只有零星几句 | 看预览文字自行决定 |
| 无人声 | 纯音乐或环境声 | 跳过，直接当画面素材用 |

判定原理：先用 Silero VAD 检测语音时长，再用 whisper 的 `no_speech_prob < 0.6`、`avg_logprob > -1.0` 过滤掉音乐上的"幻听"字幕。如果语音为 0，再关掉 VAD，抽开头、中间、结尾三个 30 秒窗口硬转复查。这一步专门防止背景乐里的对白被漏掉。

实测：10 段素材共约 13 分钟，判定耗时约 85 秒，与阿里云结果 10/10 一致，连跑两遍结果相同。

踩过的坑（改脚本时不要回退）：
- 必须 `temperature=0`。默认的随机温度重试会让同一段音频时而"无人声"、时而"存疑"。
- 纯音乐上 whisper 会编出 "Thank you for watching!" 这类套话，置信度约 -1.46。所以复查门槛定在 `avg_logprob > -1.4`，同时用套话黑名单过滤。
- 不要整段硬转长音频（会陷进幻听循环，10 段要 7 分钟），只抽三个窗口。
- 模型用本地目录路径加载。用模型名加载时，huggingface 库会联网检查，撞上本机 SOCKS 代理会直接报错。

### 3.3 阿里云转写（只送"有人声"和"存疑"）

复用 `<meeting-asr 后端目录>` 后端里的 `upload_to_oss`、`submit_transcription`、`poll_transcription`、`format_transcript` 这几个函数。不要调用它的完整流程，因为完整流程会把源文件重命名并归档进 Obsidian。

```bash
mkdir -p "<素材目录>/_audio_send" && cp <要送的 mp3> "<素材目录>/_audio_send/"
cd <meeting-asr 后端目录> && .venv/bin/python $S/asr_batch.py "<素材目录>/_audio_send" "<素材目录>/_transcripts"
```

返回 `SUCCESS_WITH_NO_VALID_FRAGMENT` 表示没有识别到人声，属于正常情况，不算报错。

### 3.4 研判转写稿

- **确认说话人身份**：是主持人、受访者还是路人？
- **找可引用的原话金句**：用作开场原声或升华段的引用，并记下时间戳。
- **补充文案里没有的事实**：落地国家、合作方、技术说法等，用作数据卡时注明出处。
- **核对专有名词**：ASR 经常识别错公司名和人名，要标出来请甲方确认。
- **找出不能外放的原声**：团队内部聊天、隐私内容要标注"静音使用"。

## 第 4 步：写大纲与分镜脚本

先确认三件事：发布平台（决定横竖屏和时长）、风格、主播是否实拍。用户没说清楚时，先问再写。

### 大纲文档结构

1. **头部信息**：平台、画幅、时长、风格、视觉基调。
2. **素材盘点表**：编号、素材、内容、用途。
3. **大纲**：分 5 到 7 段，每段写清时间、主题、形式。
4. **分镜脚本**：按段落分表，列为"镜号 | 时长 | 画面 | 旁白/台词 | 字幕/动效"。画面类型标【新闻】【主播】【动画】。
5. **包装与动效清单**、**主播实拍清单**（列出机位、台词镜号、手势镜）。
6. **音频研判结论表**。
7. **待甲方确认**：数据口径、人物姓名、竞品画面授权、外媒素材授权、措辞强度。

### 写作要点

- **先确认主播的拍摄形态再写镜头**。默认不能假设主播有全身或站姿镜头。很多科技博主是坐姿半身录播（固定机位，画框只到胸口或腰部）。写之前必须问清楚：坐姿还是站姿、半身还是全身、固定机位还是走位。一旦是坐姿半身，所有【主播】镜头的动作就只能用手势和表情，景别限制在中近景和近景，节奏要靠推拉运镜、字幕动效和素材切换来撑，不能依赖肢体动作。分镜需求里同步写明，并给分镜师一条判断依据（例如"画面里能看到桌沿或椅背就对了"）。
- **开头 3 秒决定完播**：先抛最强的背书或冲突。外媒报道、"外网炸了"制造的信息差、原声金句，都比产品介绍更抓人。
- **类比热点帮观众建立认知**（例如"像 DeepSeek 一样先海外火再火回国内"）：只用文字标签，不用对方的 logo。
- **数据卡必须有出处**：来自文案的写"数据来源：甲方"，来自采访的注明是哪段采访。没有出处的数字（例如热度计数）只能做装饰，不写具体值。
- **商业单要弱化过强或绝对化的措辞**：改写后在文档里说明，并允许用户改回原表述。
- **外景默认不让主播去拍**。老财的口播固定在办公室工位，外景成本太高。所有外景和生活场景都改用 B-roll：先用甲方官方素材；不够时用有商用授权的图库（站酷海洛、视觉中国、Pexels 等），代号记为 S。能在工位完成的插入镜头（桌面特写、录屏、手部动作）记为 R，安排和口播同一天拍。
- **官方商业片里有外籍人物或英文字幕时**，只截产品特写，避免和"个人真实分享"的调性冲突。
- **竞品对比画面只画剪影**：甲方不同意时，不用返工。

## 第 5 步：分镜绘制需求（单独一份文档）

给分镜师用，默认风格是"黑白灰简笔动作分镜"。用户另有指定时，以用户为准。

- 每张工作板为 16:9 横版，严格两行四列，共 8 个等大面板。
- 镜头较长或动作较多时拆成 a/b 两格，凑满每板 8 格。
- 每格内容写成"格 | 镜号 | 景别/时长 | 画面内容 | 标注"，画面只描述火柴人动作、道具和构图。
- 成片是竖屏时，要求每格中间用虚线画出 9:16 安全框。
- 附一段可直接套用的 AI 出图提示词：

> 绘制黑白灰简笔动作分镜工作板，整板16:9，严格两行四列八个等大面板，从上排左到右再下排左到右。角色是火柴人／线框模型，圆头几何躯体、简单肢体与表情线，只保留身份道具和最低识别轮廓；不要精修肤质、完整服装或毛发材质。

- 交付要求：先交线稿，审过再细化；PNG，宽 3840 像素；按 `<项目名>_分镜_板N.png` 命名。

脚本修改后，分镜需求里对应的格也要同步改，镜号保持一一对应。

### 5.1 用 GPT Image 直接生成分镜草图（录音豆项目实测）

用户要"生成分镜草图放进文档"时，不等分镜师，直接调用图像接口出草图。范例脚本：`$S/gen_storyboard_example.py`。复制到项目目录后，改常量 `SCRIPT_MD`、`REF_IMAGE`、`DOC_ID` 和 `STYLE` 再用。

**接口（沿用 `<其他项目 poster.py>` 和 `<其他项目目录>` 的图片编辑协议）**

- 配置文件：`<其他项目 openai.json>`，字段有 `base_url`（中转站 open.xiaojingai.com）、`api_key`、`model`、`quality`、`billing`。读配置时不打印密钥。
- 请求：`POST {base_url}/v1/images/edits`，multipart 格式。字段为 `model / prompt / n=1 / size / quality=high / output_format=png`，参考图放在 `image` 字段，不发送 `input_fidelity`。
- 返回：读 `data[0].b64_json`，没有时下载 `data[0].url`。
- 模型名用配置里的 `model`（当前是 `gpt-image-2-reverse`）。配置里的 `model_ratio: 2.5` 是计费倍率，不是模型版本，不要当成"GPT Image 2.5"。用户点名要别的型号时，问清确切的模型名，再用 `--model` 传入。
- 分镜板用 `size=1536x1024`（横版）。单张耗时 30 到 80 秒，超时设为 300 秒。多张板用多个进程并行跑。
- httpx 加 `trust_env=False`，并用 `env -u HTTP_PROXY ...` 运行，不走计费代理。
- 不做自动重试：每次调用都计费，失败后由人决定是否重跑。已生成的板默认跳过，要重画加 `--force`。
- 费用：响应里只有 `usage`（`input_tokens`、`input_tokens_details.image_tokens`、`output_tokens`），没有金额。要估算金额，按 poster.py 里 `estimate_cost_cny` 的公式套 `billing` 倍率。每次调用后应把 usage 记到本地 csv，事后才能对账（录音豆项目没记，只能去中转站后台查）。

**提示词要点**

- **参考图用产品图**：从宣传页裁出产品图作为 `image`，画出来的产品外形才准。如果有外形相近的旧款（例如录音卡和录音豆），要在提示词里写明两者的区别，否则会画混。
- **风格沿用土豆巴士已认可的写法**（`<素材下载目录>/土豆巴士/分镜/坐姿版_生成提示词.txt`）：黑白灰火柴人、白底黑线少量灰；两行四列 8 格；每格画虚线 9:16 安全框；底部信息带写"镜号 / 景别 / 时长"；坐姿主播的硬性约束（桌沿或椅背可见，无腿、无站姿，手势不高于肩）。
- **主播不画具体相貌**：只写"主播用火柴人表示"。不要自己编性别、眼镜这类外貌特征。
- **剪辑术语会被原样画进图里**："金句卡""数据卡""大字"这类前缀，要先从字幕列里剥掉，并在提示词里写明这些词不要出现在画面上。素材代号（M5、R6）也有被画出来的风险。
- **最后一板不满 8 格时**，要写明"剩余格完全留空，只画浅灰斜线，底部不写镜号"，否则模型会编出 7-3、7-4 这类不存在的镜号。
- **先跑 `--dry-run` 看提示词，再只生成第 1 板试风格**。用户认可后再批量跑，问题修完只重画有问题的板。
- **每张图生成后都要读图检查**：镜号对不对、产品外形对不对、有没有多余的字。

**放回飞书**：脚本的 `--upload` 会先追加一个"分镜草图"章节，再逐板 `+media-insert`，图注写"板 N：镜头 x 至 y"。完成后用 `docs +fetch` 回读，数一下图片数量。

## 第 6 步：交付到飞书文档（可选）

用户给了飞书文档链接、要求"把素材截图补充进文档"时走这一步。

### 6.1 抽帧

先按镜号建一个抽帧清单脚本（参考 `$S/shots.sh` 的写法：一行一个 `shot 编号 源文件 时间秒`），输出到 `_shots/final/`，文件名用 `镜号_用途` 的形式，这张图的用途一眼就能看出来。

两个必踩的坑：

- **必须加 `-vf "...,format=yuvj420p"`**。部分手机拍的素材色彩范围特殊，不加会直接报 `Non full-range YUV is non-standard` 或 `encoder init failed`，抽不出图。
- **抽完必须自己看一遍**。`tile` 拼成校验图后读一次，确认每张画的确实是该镜号要用的内容。时间点选错很常见，比如抽到转场黑帧、无关街景、或者上一镜的画面。

时间点先抽 5 到 10 个候选帧挑，比一个个试快。

- **不要用 `fps=1/N,tile` 缩略图的格子序号去反推时间点**。实测会差 1 到 2 秒，录音豆项目里有 4 个镜头因此抽错了画面。缩略图只用来粗定位，最终时间点要用 `-ss` 单独抽帧来确认。
- 本机 ffmpeg 没有 `drawtext` 滤镜，要在图上加时间码或标注时，改用 PIL。
- 一个镜头引用多段素材时（例如"磁吸 / 项链 / 会议桌"三连切），把几帧等高横向拼成一张图，图注写成"镜号：内容（M5 18s + M1 21.5s ...）"，剪辑时可以直接按图注定位。

### 6.2 插入文档

```bash
# 1) 先取真实 document_id。wiki 链接不能直接传给 +media-insert
lark-cli docs +fetch --api-version v2 --doc "<文档URL>" --scope outline --max-depth 1 \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['data']['document']['document_id'])"

# 2) 建章节标题（append 是追加到文档末尾）
lark-cli docs +update --api-version v2 --doc "<doc_id>" --command append \
  --content '<h2>九、镜头素材截图</h2><p>以下为各镜头拟使用的素材截图，抽帧自原素材，非最终调色版本。</p>'

# 3) 逐张插图，图注用文件名
for f in [0-9]*.jpg; do
  lark-cli docs +media-insert --doc "<doc_id>" --file "$f" --width 720 --caption "${f%.jpg}"
done
```

要点：

- `docs +media-insert` 只能插到**文档末尾**。要插到中间位置，改用 `docs +update --command block_insert_after --block-id <锚点>`。
- **`/wiki/...` 链接不能直接传给 `+media-insert`**，必须先换成 `document_id`，否则报错。`/docx/...` 链接可以直接传。
- `--file` 只接受**当前工作目录下的相对路径**，传绝对路径会报 `unsafe file path`。所以先 `cd` 到图片目录再跑。
- 批量插图用循环，每张一条命令，不要试图一次传多张。
- 文档里如果已经有分镜板之类的章节，不要去动，新开一节追加。

### 6.3 校验

```bash
lark-cli docs +fetch --api-version v2 --doc "<文档URL>" --scope section \
  --start-block-id <新章节id> --format pretty | grep -o 'name="[^"]*"' | sed 's/name="//;s/"//'
```

数一下图片张数和文件名，和本地对得上才算交付完成。注意 `--scope keyword` 对图片块不生效，校验要用 `section`。

### 6.4 标出需要主播实拍的镜头

分镜表交付到飞书后，要把"素材"列里的"口播"两个字标成淡黄色背景，方便主播一眼找出要录的镜头。只标"口播"两个字，同一格里的其他文字（"B 机位""+ 网络图"）不加背景。

```bash
# 取带 block id 的 XML。表格每格是 <td><p id="...">文字</p></td>，分镜表每行 7 格，第 5 格是"素材"
lark-cli docs +fetch --doc <doc_id> --detail with-ids > doc.json
# 逐格替换：只处理镜号形如 1-4 的行，跳过已含 <span 的格
lark-cli docs +update --doc <doc_id> --command block_replace --block-id <p的id> \
  --content '<p><span background-color="light-yellow">口播</span> B 机位</p>'
```

- 写入时用 `light-yellow`，回读时会变成 `rgba(255,246,122,0.8)`。校验时按 rgba 计数，不要按 `light-yellow` 计数（录音豆项目共 18 处）。
- 写脚本时，就让素材列在需要主播出镜时统一写"口播"，后面这一步才能自动标出来。注意工位插入镜头（R 类，例如对着录音豆说话、把录音豆吸到衣领）也要主播出镜，但素材列不写"口播"，不会被标黄，要在补拍清单里单独列出来。
